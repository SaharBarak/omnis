## 3. GOTCHAS (new, cost real time)

- **Expo typed routes are generated by `expo start`, not `expo export`.** A new
  screen fails `tsc` until Metro has run once and rewritten
  `packages/mobile/.expo/types/router.d.ts`. That file was stale from 22 July,
  so `/calendar` was missing from the union too.
- **The emulator's installed APK serves its own cached bundle.** The 24-July
  debug build showed a pre-P1 UI while Metro logged *zero* bundle requests —
  every "static-verified only" screen from the last session had never actually
  run. Fix: `npx expo run:android` (needs `JAVA_HOME=/opt/homebrew/opt/openjdk@17`;
  there is no `java` on PATH). ~5 min build.
- `expo run:android --device` wants an **AVD name**, not an adb serial.
- `am start -n app.pleiad.mobile/.MainActivity` opens the **dev launcher**, not
  the app. Use
  `am start -a android.intent.action.VIEW -d "exp+pleiad://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081"`.
- The dev-client's floating bubble sits exactly over the top-app-bar star.
  Drag it away (`input swipe`) before tapping anything top-right.
- **Intl non-Gregorian calendars work on Android Hermes** — Hebrew, Hijri,
  Persian and Chinese all render real dates on-device. This was the open risk
  behind P2; it is closed.
- A concurrent session edited `packages/mobile/src/lib/{supabase,env,auth/store}.ts`
  mid-run (deferred Supabase client + `isAuthConfigured`, `scripts/assert-env.mjs`).
  It broke `tsc` while half-applied. Nothing of theirs is in these commits —
  stage explicit paths, not `git add packages/mobile/src`.
